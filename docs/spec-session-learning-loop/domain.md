# Domain Analysis — Unified Learning & Memory Store (re-framed for multi-tenant scope)

**Author:** Bird (Domain Authority) · **Confidence: 80** · **Status:** re-framed for the expanded design under the locked rulings. Supersedes the prior single-user instinct-loop domain.md.

> **Scope note (Turso deferred):** v1 ships **single-user, local `bun:sqlite`**. The multi-tenant model below is designed into the schema (tenant columns + fail-closed scope predicates) so the Turso migration is a config/driver swap, but cross-tenant *enforcement and tests* are a **Turso-phase gate, not a v1 gate**. The two v1 release gates are: the shareable-tier scrub corpus (AC-2) and tier-correct migration (AC-M1).

## bounded_context

`session-learning` — re-scoped from "a retrospective instinct pipeline that sits beside file memory" to **the single unified memory store for the Dream Team**, replacing the file-based markdown memory system entirely. It still consumes `session-eval` findings (one-way, never writes back) and owns the Observation → Signal → Instinct spine. New: it now also owns the **scoped-fact tier** (the migrated `user`/`project`/`reference` memories) and a **multi-tenant access-scope model** (user_id / project_id / global) that becomes the dominant correctness concern once the store migrates to Turso and goes multi-user.

The spine of correctness has shifted. In the prior single-user design the spine was BR-9 (no identifier leaks into a shareable instinct). That invariant survives, but it is now **one of two co-equal invariants**. The second — and in a shared DB the more consequential — is **tenant isolation of scoped facts**: a scoped fact is *meant* to be identifying and is never scrubbed, so its only protection is that it physically cannot be read across its tenant boundary.

## business_context

The file-based memory system (`~/.claude/.../memory/*.md`, ~20 memories across four frontmatter types) is single-user by construction. The strategic driver for this redesign is migration to a shared Turso DB → shared store → multi-user. A DB store can carry per-row tenant scope and access control; a flat markdown directory cannot. Therefore file memory is deprecated and its contents migrate into the DB. The two kinds of knowledge the file system held map onto two tiers with fundamentally different confidentiality contracts.

## ubiquitous_language

| term | definition |
|---|---|
| **Unified store** | The single DB-backed memory store that replaces the file-based markdown memory system. Holds both tiers. Migrates local SQLite → Turso → shared → multi-user. |
| **Scoped fact** | A tier-1 memory: the migrated `user` / `project` / `reference` types. Deliberately identifying (names, emails, URLs, project state, tech stack). **NEVER scrubbed** — being identifying is its purpose. Protected solely by row-level tenant scope + access control. |
| **Shareable instinct** | A tier-2 memory: the `feedback` type plus auto-derived behavioral patterns. A generalizable behavioral heuristic, never a record of a specific client/codebase. **Scrubbed** (BR-9). The only tier eligible for promotion across projects/tenants. |
| **Tier** | The confidentiality class of a memory: `scoped` (identifying, isolated, never scrubbed) or `shareable` (behavioral, scrubbed, promotable). A memory belongs to exactly one tier and never migrates between tiers. |
| **Tenant** | The isolation principal. Concretely `user_id` (and, nested under it, `project_id`). A scoped fact belongs to exactly one tenant and is never readable outside it. |
| **Scope** | The reach of a memory: `user` / `project` / `global`. For scoped facts, scope = isolation boundary (user-scoped, project-scoped — never global). For shareable instincts, scope = injection reach (`project`, or `global` after promotion). |
| **Observation** | One graded behavioral fact from a session, derived from a stored judge `finding` (warn/fail + verbatim evidence). Session-bound, not generalized. |
| **Signal** | An observation reduced to its generalizable behavioral shape, stripped of session particulars. The unit counted toward the auto-inferred ≥3 threshold. |
| **Instinct** | Atomic reusable know-how, a shareable-tier member: `id · trigger · behavioral_shape · confidence(0.3–0.9) · domain · scope · evidence · TTL · status · ingestion_path`. A pattern, never a record of a specific client. |
| **Ingestion path** | How a shareable instinct entered the store. Three values: `auto_inferred` (the analyzer spotted a recurring signal), `human_directive` (the user stated an explicit standing directive in-session), or `migrated` (one-time import from a file-based `feedback` memory via `import-file-memory.ts`). The path determines occurrence threshold, confidence, and approval semantics. *(added per Bird ruling 2026-06-26, Slice 8 migration)* |
| **Auto-inferred instinct** | An instinct the analyzer derives statistically from recurring warn/fail signals. Requires ≥3 distinct sessions (BR-1). Stored `status='pending'`; needs explicit human approval (BR-13). |
| **Human-directive instinct** | An instinct captured because the user stated an explicit standing directive at session end ("from now on, never take a public action without asking"). Coach K analyzes the full transcript and surfaces it as a candidate. **n=1 — no occurrence threshold** (BR-1a). Ground truth on occurrence 1. Confidence fixed at 0.9 (OQ-1 resolved). |
| **In-session approval (the closed loop)** | Approval is a step *inside* the loop, presented synchronously at session end while context is fresh — never a notification, queue, or pull-when-you-remember surface. For a human-directive, the statement, capture, and approval are the **same in-session event**: stated → captured → confirmed in-session → stored approved. The confirmation **keystroke** is the trust anchor (not transcript text). |
| **Scrub / leak guard** | Mandatory, deterministic, non-LLM, post-generation gate. DROPs (never redacts) any *shareable-tier* candidate carrying client-identifying content OR malicious/imperative shapes. **Applies to the shareable tier only** — scoped facts are never scrubbed. |
| **Promotion** | `project → global` for a shareable instinct. A scoped fact is **never promotable**. An instinct must pass the scrub gate before it may be promoted across tenants. (Deferred to v1.1/Turso.) |
| **Injection** | Surfacing memory at SessionStart. Shareable instincts inject as untrusted advisory heuristics (approved, ≥0.7, capped ≤6). Scoped facts inject as trusted memory, only within their own tenant. The only point a stored memory influences behavior. |
| **Migration** | The one-time import of the ~20 file memories into the DB, classifying each by frontmatter `type` into the correct tier: `user`/`project`/`reference` → scoped; `feedback` → shareable. |
| **Cross-tenant fact access** | The scoped-tier leak: tenant A reads tenant B's scoped fact. The new dominant threat (materializes at Turso/multi-user). |
| **Cross-tenant behavioral injection** | The shareable-tier leak: a pattern carrying tenant B's identifiers (or a directive issued only for tenant B) is injected into tenant A's session. The old BR-9 threat, framed across tenants. |

## business_rules

**Tier classification & migration**

- **BR-T1** — Every memory belongs to exactly one tier: `scoped` (types `user`/`project`/`reference`) or `shareable` (type `feedback` + auto-derived patterns). `invariant: true`. The tier determines the confidentiality contract (scrub vs no-scrub, isolated vs promotable). *Testable:* every row has a non-null tier ∈ {scoped, shareable}; no row has both contracts applied.
- **BR-T2** — A memory never crosses tiers after classification. `invariant: true`. A scoped fact moving to shareable would be promotable-yet-never-scrubbed = guaranteed leak; a shareable instinct moving to scoped would lose its scrub guarantee. *Testable:* no update path sets `tier` to a different value; tier is immutable post-insert.
- **BR-M1** — File-memory migration maps all four frontmatter types to the correct tier: `user`→scoped(user), `project`→scoped(project), `reference`→scoped(reference), `feedback`→shareable. Classify by frontmatter `type`, authoritative over filename (OQ-4 resolved). `invariant: false` (correctable by re-running). *Testable:* migrate the 20 known files; assert each lands per its `type`; zero `feedback` in scoped, zero `user`/`project`/`reference` in shareable; mismatched filename/type pairs logged for human review.
- **BR-M2** — A migrated `feedback` memory entering the shareable tier passes the scrub gate exactly like an auto-inferred candidate; one that fails scrub is DROPped, not imported. `invariant: true`. *Testable:* seed a `feedback` file containing an identifier; assert it is not imported into the shareable tier.

- **BR-MIG-3a** *(added per Bird ruling 2026-06-26, Slice 8 migration)* — Migrated `feedback` MUST pass the full shareable-tier scrub gate (BR-9 + C-1/C-2 hardening); trusted-at-rest ≠ shareable-safe. - **BR-MIG-4** *(added per Bird ruling 2026-06-26, Slice 8 migration)* — Any `feedback` file DROPped by the scrub gate is appended to the re-authoring WORKLIST (source filename + matched rule + masked excerpt); NEVER silently lost. `invariant: true`. *Testable:* AC-MIG-5.
- **BR-MIG-5** *(added per Bird ruling 2026-06-26, Slice 8 migration)* — Migration is idempotent; dedup by `content_key` (facts) / `identity_key` (instincts); re-run = upsert, never duplicate rows. `invariant: true`. *Testable:* AC-MIG-6.
- **BR-MIG-6** *(added per Bird ruling 2026-06-26, Slice 8 migration)* — Source markdown is ARCHIVED (copied to `memory/archive/`), NEVER deleted or moved. The migration REPORT must be human-reviewed before the REPLACE cutover (built-in auto-memory disable) is executed. `invariant: false` (process gate). *Testable:* AC-MIG-7; AC-MIG-11.
- **BR-MIG-7** *(added per Bird ruling 2026-06-26, Slice 8 migration)* — Unrecognized or missing `type` value → SKIP + log to worklist ("needs human classification"); NEVER default a tier (fail-safe). `invariant: true`. *Testable:* AC-MIG-8.
- **BR-MIG-8** *(added per Bird ruling 2026-06-26, Slice 8 migration)* — `MEMORY.md` is skipped during migration; it is a regenerable index, not a memory, and must not be processed, archived, or imported. `invariant: true`. *Testable:* AC-MIG-9.
- **BR-MIG-9** *(added per Bird ruling 2026-06-26, Slice 8 migration)* — `[[wikilink]]` text in imported content is preserved VERBATIM; links are NOT resolved during migration (the `memory_links` table is deferred to v1.1). `invariant: false` (deferred resolution). *Testable:* a file containing `[[some-link]]` → stored content contains `[[some-link]]` unchanged.
- **BR-MIG-10** *(added per Bird ruling 2026-06-26, Slice 8 migration)* — All migrated instincts are team-wide (`agent_id = NULL`) in v1, even if the source file's name or content implies an agent-specific pattern. Consistent with BR-AG1. `invariant: false` (v1 default). *Testable:* AC-MIG-4 (agent_id NULL on every migrated instinct row).
- **BR-MIG-11** *(added per Bird ruling 2026-06-26, Slice 8 migration)* — The WORKLIST and migration REPORT are HUMAN-ONLY artifacts; they MUST NOT be projected into `MEMORY.md` and MUST NOT be fed to the session analyzer, because they may contain client identifiers from DROPped content. `invariant: true`. *Testable:* AC-MIG-10.

**Multi-tenant access scope (the new spine — enforced at the Turso phase, schema-ready in v1)**

- **BR-S1** — A scoped fact is readable, injectable, and listable ONLY within its own tenant (user_id, and project_id where set). It NEVER crosses its tenant boundary. `invariant: true`. Scoped facts are deliberately identifying and never scrubbed; tenant isolation is their *only* protection. *Testable (Turso-phase gate):* every read/inject/list query is filtered by the caller's tenant; a query without a tenant predicate returns zero scoped rows (fail-closed), never all rows.
- **BR-S2** — A scoped fact has no global scope and is never promoted. `invariant: true`. *Testable:* no path writes a scoped row with scope=global or runs promotion on a scoped row.
- **BR-S3** — A shareable instinct may be promoted across tenants ONLY after passing the scrub gate; promotion to global is allowed only for scrubbed shareable instincts. `invariant: true`. *Testable:* a candidate that has not passed scrub cannot be set scope=global.
- **BR-S4** — Access control is fail-closed: any query that cannot resolve a caller tenant returns no scoped rows and no tenant-specific instincts. `invariant: true`. *Testable:* null/absent tenant context → empty scoped result set, never a full-table scan.

**Shareable-tier ingestion (carried forward + new human-directive path)**

- **BR-1** *(carried)* — An **auto-inferred** instinct exists only if its signal occurred in ≥3 distinct sessions. `invariant: true`. *Testable:* 2 sessions → no auto instinct; 3rd distinct → exactly one. **Applies to `ingestion_path='auto_inferred'` only.**
- **BR-1a** *(NEW)* — A **human-directive** instinct is captured at n=1: a single explicit user directive at session end is ground truth and requires no occurrence threshold. `invariant: false`. *Testable:* one session with an explicit, in-session-confirmed user directive → exactly one instinct with `ingestion_path='human_directive'`, occurrence_count=1; no ≥3 requirement.
- **BR-2** *(carried)* — Confidence ∈ [0.3, 0.9], derived deterministically from evidence for auto-inferred, never accepted from the LLM. `invariant: true`. **Human-directive instincts are stored at fixed 0.9** (OQ-1 resolved — ground truth, exempt from evidence-derivation). **Scope: the fixed-0.9 applies to the LIVE `human_directive` path only; the `migrated` path uses 0.7 (see BR-MIG-3 — added per Bird ruling 2026-06-26, Slice 8 migration).** *Testable:* out-of-range rejected; model-supplied value ignored for auto; directive = 0.9; migrated = 0.7.
- **BR-2.1** *(NEW — added per Bird ruling 2026-06-26, Slice 4)* — Auto-inferred confidence = `ROUND(clamp(0.50 + 0.05·(S−3) + 0.15·R, 0.30, 0.90), 2)`, where S = COUNT(DISTINCT session_id) for the identity_key, R = fail-session fraction (# distinct sessions whose max contributing severity = 'fail', ÷ S). Coefficients are tunable policy. `invariant: false` (policy). **Rounding authority is SQL `ROUND(,2)`** (single authority, consistent with the projection compare) — NOT a separate TS rounding step. *Testable:* AC-H2-1 through AC-H2-4.
- **BR-2.2** *(NEW — invariant — added per Bird ruling 2026-06-26, Slice 4)* — Confidence is derived in TS/SQL from the evidence set only; never accepted from the LLM; never a function of `now()` (time-dependence would break the projection's byte-identical determinism). `invariant: true`. *Testable:* AC-H2-6 (identical confidence values at two different wall-clock times, identical DB state).
- **BR-2.3** *(NEW — invariant — added per Bird ruling 2026-06-26, Slice 4)* — Confidence is recomputed (not delta-incremented) in-transaction on every upsert from the current distinct-session set; rises monotonically with reinforcement; hard-capped 0.90. `invariant: true`. *Testable:* AC-H2-5 (re-score with unchanged severity → S and confidence unchanged; flip warn→fail → confidence recomputes upward; occurrence_count unchanged in both cases).
- **BR-2.4** *(NEW — added per Bird ruling 2026-06-26, Slice 4)* — A freshly materialized 3-session instinct (S=3, R=0) has confidence=0.50, which is below the 0.7 injection threshold — it is not injection-eligible until further reinforced. This separates the existence gate (BR-1: ≥3 sessions to materialize) from the injection gate (BR-4: confidence ≥ 0.7 to project). `invariant: false` (policy threshold). *Testable:* AC-H2-1.
- **BR-3** *(carried, narrowed)* — A newly-extracted **auto-inferred** instinct is stored scope=`project`. `invariant: true`.
- **BR-9** *(carried — co-spine; **UNCHANGED by Bird ruling 2026-06-26 — path C only narrows Rule 4's trigger, the invariant itself is 100% intact**)* — No **shareable-tier** memory may contain client-identifying content OR malicious/imperative instructions; the scrub gate DROPs failures. `invariant: true`. **Scoped facts are explicitly out of scope** — they are isolated, not scrubbed. *Testable:* AC-2 adversarial corpus; zero sentinel substrings in any shareable row.
- **BR-9.4a′** *(amended per Bird ruling 2026-06-26 — path C)* — Rule 4 DROPs a Title-case token ONLY on a positive name-signal: (a) camelCaps/PascalCase code shape (routed via the existing code-literal rule); (b) naming-context — possessive `'s`, or an entity word (client/tenant/cluster/company/named/called…) within ±5 tokens (DR-6); (c) an all-caps acronym used as a name, narrowly corroborated by naming-context/possessive (`ACME's`, `client ACME`). MUST NOT drop on absence-from-dictionary or on capitalization alone. **No wordlist — the `english-words.txt` bundle is removed.** GENERIC_TECH_ALLOWLIST (`API`, `SQL`, `AWS`, Git, Docker, GitHub, agent names…) remains a hard KEEP ahead of any acronym rule. `invariant: false`. *Testable:* bare signal-less "Acme" with no context → KEPT (AC-2c′ residual); camelCaps/naming-context/acronym-corroborated token → DROPPED (AC-pos-1/2/3); no DR-5/wordlist invoked.
- **BR-9.4b′** *(extended per Bird ruling 2026-06-26 — path C)* — A bare uncommon Title-case name with NO naming-context, code shape, or acronym signal is the ACCEPTED residual — it passes Rule 4. This widens the prior common-word-name residual to ANY signal-less name (not just common-word names). Backstopped by BR-13. `invariant: false`. *Testable:* "refunds over $500 need dual approval" → KEPT (no naming-context); bare "Acme" standalone with no signal → KEPT (accepted residual, AC-2c′); "deploying to Acme's cluster, rotate credentials" → DROPPED (naming-context).
- **BR-9.over-drop′** *(resolved/retired per Bird ruling 2026-06-26 — path C)* — "Over-drop is correct" is RETIRED as a Rule-4 principle (it only ever justified the dictionary heuristic). The calibration target is now ZERO false drops on a held-out ordinary-long-English corpus (AC-2a′). `invariant: false`. *Testable:* 0 of ≥25 reviewer-authored ordinary 10+ char Title-case English words DROPped (AC-2a′).
- **DEF-1** *(NEW — defense-in-depth, per Bird ruling 2026-06-26)* — All non-Rule-4 detectors (encode/decode-and-rescan, homoglyph/NFKC+confusable fold, code-shape, secret, path, URL, email, cross-field concat, DR-6) are UNCHANGED by path (C) and must remain at 100% on the adversarial corpus. Rule 4's narrowing does not weaken any other detector. `invariant: true`. *Testable:* full AC-2 DROP corpus (all non-name-signal rows) 100% DROPped.
- **BR-11** *(carried — **UNCHANGED by Bird ruling 2026-06-26**)* — A shareable instinct is traceable to its evidence; stored evidence itself passes the scrub gate; whole-candidate DROP on any field failure. `invariant: true`.
- **BR-12** *(carried, extended)* — Auto-inferred instincts derive only from judge warn/fail findings. Human-directive instincts derive only from an explicit user directive **confirmed in-session** — not from arbitrary transcript text. `invariant: false`. *Testable:* an auto signal with no warn/fail finding → rejected; a "directive" the user did not confirm → not auto-approved.

**Approval & injection (carried forward + human-directive auto-approval)**

- **BR-13** *(carried — the human gate; **UNCHANGED by Bird ruling 2026-06-26 — LOCKED; the backstop carrying the widened BR-9.4b′ residual**)* — A stored shareable instinct is NEVER injected until a human has explicitly approved it (`status='approved'`). `invariant: true`.
- **BR-13a** *(NEW — how human-directive satisfies BR-13 inherently)* — For a human-directive, the user's in-session confirmation IS the approval: stated → captured → confirmed in-session → stored `status='approved'` in the same closed-loop event, because the approving human and the directing human are the same person, present with full context. The **confirmation keystroke is the trust anchor**, NOT transcript text. `invariant: false`. *Testable:* a confirmed directive is stored approved; an unconfirmed candidate stays `pending`, never auto-approved.
- **BR-13b** *(NEW — invariant — added per Bird ruling 2026-06-26, Slice 4)* — A human-directive cannot reach `status='approved'` if `norm(content) === norm(suggestion)` or `norm(content)` is empty, where `norm` = NFKC → lowercase → strip to `[a-z0-9 ]` → collapse whitespace → trim. Trailing-space, case, or punctuation-only changes are treated as non-authored. `invariant: true`. *Testable:* AC-13b-1.
- **BR-13c** *(NEW — added per Bird ruling 2026-06-26, Slice 4)* — Acceptance requires the normalized alphanumeric token sequence to differ by ≥1 word; no edit-distance or quality threshold beyond that minimum. `invariant: false`. *Testable:* AC-13c-1 (delete one letter changing a word → accepted; delete only a space → rejected because token sequence is unchanged).
- **BR-13d** *(NEW — invariant — added per Bird ruling 2026-06-26, Slice 4)* — Directive state machine ordering: capture → scrub → authorship guard → keystroke→approved. The scrub gate (BR-9/C-1 imperative detector) applies to human-authored directives unconditionally — a human may direct a policy, never an executable imperative. scrub fail → DROP (no row written); authorship-equal → REJECT (no approved row); no keystroke → pending. `invariant: true`. **Documented accepted residual:** the deterministic scrub gate DROPs the enumerated disable/weaken-safety class (e.g. "disable the pre-commit hook") and clear executable imperatives (`curl|sh`), but CANNOT catch semantic paraphrases ("stop running the hook", "comment out the hook", "ignore the failing tests") by construction — this is the same reason the wordlist approach was retired. Those paraphrases are the accepted residual, backstopped by the human authorship guard + human approval; the gate does NOT chase paraphrases. *Testable:* AC-13d-1, AC-13d-2.
- **BR-13e** *(NEW — invariant — added per Bird ruling 2026-06-26, Slice 4)* — The machine `suggested_content` is persisted on the directive row (BR-13a auditability; corresponds to the `suggested_content TEXT` nullable column on `instincts` — schema delta per Slice 4); for multi-field directives, the equality guard (BR-13b) binds at minimum to `behavioral_shape`. `invariant: true`. *Testable:* AC-13e-1 (multi-field directive edited only in `trigger` with `behavioral_shape` identical to suggestion → REJECTED).
- **BR-4** *(carried)* — Injection fires only for confidence ≥ 0.7. `invariant: false`.
- **BR-5** *(carried)* — ≤6 shareable instincts injected per SessionStart. `invariant: false`.
- **BR-6** *(carried)* — On injection, a project instinct wins over a same-pattern global. `invariant: false`.
- **BR-8′** *(amended per Bird ruling 2026-06-26, TTL)* — Staleness pruning (30 days) applies to `ingestion_path='auto_inferred'` ONLY. The prune DELETE, the `selectForProjection` freshness filter, and the `countEligible` freshness filter MUST each guard on `ingestion_path='auto_inferred'`; `migrated` and `human_directive` instincts are TTL-EXEMPT (like scoped_facts). Review OR new occurrence resets the clock for `auto_inferred` rows. `invariant: false`. *Testable:* `auto_inferred` 31 days stale → pruned (AC-TTL-3); `migrated` or `human_directive` 31 days without review → NOT pruned (AC-TTL-1, AC-TTL-2); 29-day `auto_inferred` → survives (AC-TTL-3). **Scoped facts do NOT auto-prune** (OQ-3 resolved — deletion is an explicit user action).
- **BR-8a′** *(new — amended per Bird ruling 2026-06-26, TTL)* — Human-authored shareable instincts (`ingestion_path ∈ {'migrated','human_directive'}`) MUST NOT be removed by any time-based or passive mechanism; they may be removed only by explicit human action (`status='rejected'` via `setStatus`). `invariant: true` (no silent loss of human-curated content; consistent with OQ-3 + BR-MIG-6). *Testable:* AC-TTL-1 (migrated instinct 31 days old → NOT pruned), AC-TTL-2 (human_directive 31 days old → NOT pruned).
- **BR-8b′** *(new — amended per Bird ruling 2026-06-26, TTL)* — TTL-exemption does NOT relax the injection bound — BR-5 (≤6 injected), BR-4 (ROUND(conf,2)≥0.7), BR-13 (approved-only), and BR-6 (project-over-global dedup) still bind all projected instincts regardless of ingestion path. `invariant: false` (policy caps). *Testable:* AC-TTL-5 (50 approved migrated/directive instincts >0.7 → ≤6 in projected index; BR-5 holds under exemption).
- **BR-8c′** *(new — amended per Bird ruling 2026-06-26, TTL)* — Removal of a human-authored instinct is via `setStatus(id,'rejected')`; rejected rows are excluded from all `selectForProjection` and `countEligible` queries (consistent with BR-13). `invariant: true`. *Testable:* AC-TTL-6 (migrated instinct set `status='rejected'` → excluded from selectForProjection + countEligible).
- **BR-10** *(carried)* — Off by default; opt-in env var enables; never blocks session exit (except the locked in-session approval path under the learning opt-in); never sends/pushes externally beyond the sanctioned Turso sync. `invariant: true (never-externalize beyond sanctioned sync) / false (toggle)`.

**Agent-scoping + forward-compat invariants (added per Bird ruling 2026-06-26, agent-scoping)**

- **BR-AG1** *(NEW)* — The agent axis is a scoping dimension (team-wide vs. exactly-one-roster-agent); new instincts default team-wide. **v1: every instinct is team-wide.** `invariant: false` (v1 default; becomes a per-row attribute in v1.1). *Testable:* v1 — every row has `agent_id IS NULL` (team-wide sentinel); no v1 code path writes a non-NULL `agent_id`.
- **BR-AG2** *(NEW — invariant)* — The `agent_id` value vocabulary is **roster-bounded**: only the fixed Dream Team roster names (`mj`, `bird`, `shaq`, `kobe`, `pippen`, `magic`, `drexler`) are valid non-NULL values; free-text agent values are rejected at the write boundary. `invariant: true`. *Testable:* attempt to write `agent_id='unknown-agent'` → rejected; each of the seven roster names → accepted.
- **BR-AG3** *(NEW — invariant, data integrity)* — If/when `agent_id` joins the uniqueness key, it MUST be represented as `COALESCE(agent_id,'*')` (a NOT-NULL sentinel), never as a raw nullable column in the index. SQLite treats `NULL` as distinct in UNIQUE constraints — a nullable `agent_id` in the key silently disables `(tenant_id, identity_key, scope, project)` dedup, corrupting BR-1/BR-6/the upsert. **v1: `agent_id` is a dormant nullable column NOT in the uniqueness key; the v1 index is `(tenant_id, identity_key, scope, COALESCE(project,''))` with no `agent_id` term.** When `agent_id` enters the key in v1.1 it MUST use the `COALESCE(agent_id,'*')` form. `invariant: true`. *Testable:* two instincts identical on `(tenant_id, identity_key, scope, project)`, both team-wide (`agent_id IS NULL`) → collide/upsert to ONE row (dedup intact, confirming the v1 index does not carry the NULL-distinct landmine).
- **BR-AG4** *(NEW)* — Specificity precedence (v1.1): `(agent-match, project) > (agent-match, global) > (team-wide, project) > (team-wide, global)`. **Collapses to BR-6 in v1** (all rows team-wide). `invariant: false` (v1.1 feature). *Testable (v1.1):* team-wide + shaq-specific same `identity_key`; projecting for shaq → shaq-specific wins; projecting for bird → team-wide used.
- **BR-AG5** *(NEW — v1 dormancy)* — All v1 queries — materialization, scrub gate, approval, projection selection, dedup, TTL prune — MUST NOT reference the `agent_id` column. Output is byte-identical to an agent-less design. `invariant: false` (structural safety in v1). *Testable:* grep asserts no v1 query string references `agent_id`; AC-AG1 end-to-end run produces output byte-identical to a build without the column.
- **BR-AG6** *(NEW)* — Agent-scoping does NOT alter the co-spine: an agent-scoped instinct (v1.1) is still scrubbed (BR-9), still requires ≥3 sessions (auto) / n=1 (directive), still requires human approval (BR-13), and is still TTL-pruned (BR-8). A roster name appearing in instinct *text* (not the `agent_id` column) is KEPT by the scrub gate — roster names are on the `GENERIC_TECH_ALLOWLIST` (consistent with BR-9.4a′). `invariant: false`. *Testable:* instinct text containing "shaq" or "magic" (roster names) → passes scrub, KEPT; no allowlist regression.
- **BR-EMB1** *(NEW — forward-compat invariant)* — Any future embedding is derived ONLY from post-scrub content; never from a `scoped_fact` in a tenant-crossing form. Embeddings are considered invertible — a pre-scrub embedding is a leak around BR-9; a cross-tenant embedding from a scoped fact violates BR-S1. `invariant: true`. *Testable (forward):* embedding generation code path asserts its input is the `behavioral_shape` + `trigger` columns of a scrub-passed instinct, not the raw LLM candidate or any scoped-fact field.
- **BR-LNK1** *(NEW — forward-compat invariant)* — `memory_links` (deferred table, per slice3-design §2) are tier- and tenant-respecting: a link MUST NOT be traversed or projected in a way that promotes scoped/identifying content into the shareable tier or across a tenant boundary. `invariant: true`. *Testable (forward):* link-traversal query asserts the target row's `tenant_id` matches the caller's tenant and the target's tier ≤ the source's tier (scoped→scoped within same tenant only; shareable→shareable only).

## acceptance_criteria

- **AC-1a (v1) — human-directive n=1 + auto-approval:** a session where the user states an explicit standing directive and confirms it in-session → exactly one instinct (`human_directive`, occurrence_count=1, confidence=0.9, status='approved'), no ≥3 threshold.

## edge_cases

- **The human-directive abuse hole (most important).** Mitigations that MUST hold: (1) auto-approval requires **in-session confirmation by the directing human** (the keystroke) — a captured-but-unconfirmed directive stays `pending` (BR-13a / AC-1b); (2) the human-directive instinct is **still shareable-tier and still scrubbed** — BR-9's imperative/command-shape detector DROPs `curl … | sh`, "disable the pre-commit hook", etc., even when human-stated (a human may direct a *policy*, not smuggle an executable imperative); (3) auto-approval is **tenant-scoped** — promotion across tenants still requires scrub + distinctness. n=1 ground-truth applies to *occurrence sufficiency*, not to bypassing the scrub gate or the tenant boundary.
- **One user's directive becoming another's instinct.** A directive is ground truth for the issuing tenant only; it must NOT auto-promote on n=1 (OQ-2 resolved — tenant-local; cross-tenant only via scrub + ≥2 distinct tenants).
- **A scoped fact mis-tiered into the shareable store.** Catastrophic (promotable + never scrubbed). Defended by BR-T1/BR-T2 (tier assigned at insert by `type`, immutable).
- **Migration mis-classifying a memory.** Map strictly by frontmatter `type` (BR-M1); shareable-bound items still pass scrub (BR-M2); filename/type mismatches (e.g. a `user_`-prefixed file with `type: project`) classified by `type`, mismatch logged for human review.
- **Generically-phrased proprietary domain rule** ("refunds over $500 need dual approval") — **KEPT by the deterministic gate** (this is correct behavior, not a gap: no identifier, no named entity, no naming-context). The human-approval gate (BR-13) is the documented backstop for this semantic-confidentiality class. Often *better expressed as a scoped project fact* (isolated, not scrubbed) — surface this at capture time. Note: the AC-2 corpus row for this case was previously stated as "→ DROPPED" — that was an error and is corrected to "→ KEPT" (Bird ruling).
- **A bare signal-less name** — whether a common English word ("Apple", "Signal") or an uncommon proper name ("Acme", "Contoso") — with NO naming-context, code shape, or acronym corroboration passes Rule 4 per BR-9.4b′ (accepted residual widened from common-word-only to ANY signal-less name). Backstopped by BR-13 + the human-authored-text requirement (BR-13a). Not a test failure. The failure mode deliberately flips from over-drop (silent, unrecoverable loss of legitimate instincts) to under-drop (visible, backstopped by BR-13's mandatory human gate).
- Carried: chatty single session = 1 occurrence; boundary values (0.3/0.9, 0.70 eligible, 0.79999 not promotable); re-scored session must not double-count; cap starvation → deterministic recency tiebreak.

## business_impact

- **Financial:** low direct cost (mirrors detached-worker + SQLite patterns); Turso adds a managed-DB line item but unlocks the multi-user surface. Dominant risk is reputational/contractual — a cross-tenant scoped-fact leak in a shared DB is a confidentiality-breach class event.
- **Operational:** replacing two systems with one removes the markdown-directory maintenance burden. Risk concentrates in two gates exercised in CI: the scrub gate (shareable) and (at Turso) the tenant-isolation predicate (scoped).
- **User:** the human-directive n=1 path is a major UX win — say "from now on never X" once, at session end, and it sticks immediately, because statement and approval are the same event. Closes the loop the file system left open (the user had to remember to hand-write a `feedback_*.md`).
- **Risk:** two co-equal invariants — shareable-tier leak guard (BR-9, v1 gate) and scoped-tier tenant isolation (BR-S1, Turso-phase gate). The human-directive path adds a third managed risk (n=1 authorization), bounded by in-session confirmation + scrub + tenant boundary.
